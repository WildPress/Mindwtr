# Native iOS development client

This is the SwiftUI/JavaScriptCore foundation from [ADR 0029](../../docs/adr/0029-native-clients-host-the-typescript-core.md). React Native in `apps/mobile/` remains the production client. This project is not a replacement build or a TestFlight release.

The app uses the existing bundle identifier only on a simulator, and normally stores its disposable library under its own `Application Support/NativeFoundation` directory. Physical alpha testing requires a Debug build with `NATIVE_DEVICE_TEST` and the separate `tech.dongdongbh.mindwtr.native.dev` identifier; startup rejects any other physical identity before opening storage. It does not open the live RN library, credentials, App Groups or sync destinations. Do not install it over the RN app. Project defaults keep signing disabled; device testing uses existing development signing assets explicitly.

## Build and check

Use the repository's existing JavaScript dependencies. On a Mac with Xcode installed, from the repository root:

```sh
bash apps/ios-native/scripts/validate.sh
```

This generates `Resources/core-host.js`, runs the Swift package's real JavaScriptCore/SQLite tests, and builds the simulator application without signing. Build artifacts and temporary files stay under `apps/ios-native/.build/`. The tracked `MindwtrNative.xcodeproj` and shared scheme are independent of Expo prebuild and CocoaPods.

## Architecture and scope

One application-owned host serializes JavaScriptCore and SQLite work away from the main thread. Swift executes SQL requested by the existing core adapter; task rules and persistence acknowledgments remain in `packages/core`. The foundation reuses the Android host's JavaScript entry and runtime shims. JavaScriptCore supplies real `Intl`; it does not use a substitute collator.

Inbox and Focus rows, revisions, metadata, translations and capture parsing come from core. Focus keeps core's section order, counts and timed labels, supports collapsed sections and bounded grouped paging, and refreshes while foregrounded without dropping loaded pages. Its filters retain RN's include/exclude cycle, All/Any choices, project/priority/energy/estimate/location controls, transient sort and existing saved-filter selection. Picker search and paging reach all options. Filter controls persist through editor, Search and area navigation and reset on restart; saved-filter writes, grouping changes, star and reorder remain pending. Focus Show details persists locally across restarts, with strict boolean import from copied RN preferences. Description previews reuse core Markdown resolution; Task/Project links navigate to their actual destinations, and plain description/age taps open the source Task. Normal/largest simulator, copied-RN preference and physical iPhone checks passed with unrelated data preserved. Section folds now persist locally too. The toolbar follows RN by opening Today’s Focus and expanding/collapsing all five other sections, including hidden ones. Copied-RN imports preserve strict boolean and legacy nextActions behavior; local native choices take precedence. Area selection uses core's include/exclude cycle and persists its final state. Task details render core's Markdown and checklist windows; the editor supports title, notes, priority, energy, time estimates, contexts/tags with suggestions and quick choices, start/due/review dates, relative scheduling, recurrence rules with the shared next-calendar-preview hint and existing project/area/section destinations through core-provided layout and options, with unsaved preview, save and discard. Global Search uses core's matching, highlighting, filters and completion eligibility, preserves its query through task editing, and returns to its caller. Menu opens the core-grouped Projects list; project details retain core task/section ordering and bounded pages, with read-only previews for archived projects. Contexts retains RN’s chip search, All/None and All/Any selection, token/project navigation and bounded task pages, preserving selections through task editing and Search. Its bulk, swipe and undo actions remain pending. Waiting shows core person filters, task pages and deferred projects, preserving its person selection through task editing and Search. Someday retains core grouping, sorting, details and filter state, with bounded task/section and picker pages; token include/exclude filters and task editing return to the same view. Reference uses the same filter controls, core grouping and stored sort, with opt-in read-only archived-project previews and project links. History keeps separate Done and Archived filters, task/project segments and loaded pages; Trash renders core’s read-only deletion timeline and retention labels. Restore, purge, archive actions and persisted History view choices remain pending. The SwiftUI interface follows RN's tabs, task cards, colors, capture layout and Edit/Preview controls. Missing screens and controls are migration work, not approved UX differences. The host creates a consistent prewrite recovery checkpoint before core schema initialization. Failed loads prevent activation. Before capture writes, core prepares the task and optional project, and the host journals their complete values. Restart retries those values without reparsing the text under a different clock, timezone or setting. Startup normalization and maintenance wait until journal recovery finishes, then run before the UI becomes available. Pending mutations remain blocked until their durable result and journal cleanup are known. Old raw-capture journals fail closed because they cannot be reconstructed reliably. Editor saves journal changed title/description/priority/energy/estimate fields and their original values. Destination changes journal the full original and desired project/area/section tuple so another writer’s section assignment cannot be silently cleared. Core recognizes its canonical saved title on restart and refuses conflicting newer edits. Core rejects priority/estimate writes that Reference tasks cannot retain. Date saves prepare and journal exact core-derived changes before writing, preserving date-only, floating and timed values across timezone changes and restart. Conflicting date or scheduling changes fail closed; exact retries do not reschedule twice. Relative amounts retain raw text while focused and drain accepted edits before Save or Preview. Shared drafts retain their opening date projections through JSON recovery so a timezone change cannot turn an untouched timed date into an edit. Recurrence edits use the same prepared-save path, retaining opening recurrence and schedule baselines and freezing core-derived changes before persistence. Recovery retains series metadata and exact dates; editing alone creates no next task. Status and other remaining editor fields stay outside this write path until their replay behavior is implemented. Drafts not yet submitted for save currently remain in memory.

The package also rehearses RN storage upgrades through an explicit debug initializer: it checks the original backup before opening SQLite, preserves a recovery checkpoint, imports through core, then updates RN migration markers. Missing SQLite-era databases and malformed or lossy backups fail closed. Debug simulator launches with `--native-rn-rehearsal` require an explicitly staged container copy under `Application Support/NativeRNRehearsal`, including `Documents/SQLite/mindwtr.db` and the original relative AsyncStorage paths. That mode reads the copy's language, theme and Add another preference; it never selects the live RN container. See [upgrade safety and remaining gates](../../docs/development/native-ios-upgrade-safety.md). These rehearsals do not establish signed replacement-install safety.
